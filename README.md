# TagUp Backend

친구끼리 초대코드로 방을 만들어 **KBO 경기를 보면서 타석마다 내기**를 거는 앱의 서버.

내기 대상은 돈이 아니라 "커피 한 잔", "치킨 사기" 같은 텍스트다. 타석이 시작되면 방에
중계 메시지가 뜨고, 아웃이냐 세이프냐에 걸 수 있다. 타석이 끝나면 **서버가 결과를 보고
자동으로 정산한다.**

- 프론트엔드: [tagup-frontend](https://github.com/SangHyun-e/tagup-frontend) (React Native + Expo)
- Java 25 / Spring Boot 4.1 / JPA · QueryDSL / Firebase Auth · Firestore

|---|---|---|---|---|
| 2026-09-30 | 404건 | 253 / 134 / 17 | **95.8%** | 0회 |
| 2026-10-01 | 319건 | 197 / 118 / 4 | **98.7%** | 0회 |
| 2026-10-12 (포스트시즌) | 245건 | 150 / 85 / 10 | **95.9%** | 0회 |

**968타석, 중계 메시지 351건, 폴링 공백 0회.**

"정산 가능"은 아웃/세이프 중 하나로 **판정이 갈린 비율**이다. 나머지는 판정불가로 남기고
내기를 무효 처리한다 — 애매한 걸 억지로 판정하느니 무르는 쪽이 낫다.

## 까다로웠던 문제들

### KBO가 가끔 과거 스냅샷을 돌려준다

15초마다 `GetKboGameList`를 긁는데, 종종 **이전 상태의 응답**이 섞여 온다. 7회 2아웃이던
경기가 갑자기 5회 1아웃으로 보이는 식이다. 그대로 믿으면 없던 타석이 생기고, 한 번은
**가짜 이벤트로 내기가 정산됐다.**

`StaleSnapshotGuard`가 이닝·점수가 역행하는 스냅샷을 거른다. 다만 무조건 버리면 안 된다 —
KBO가 **정정**을 내보내는 경우도 있어서, 같은 역행이 연속 20회 들어오면 그게 진짜라고
보고 받아들인다. 아웃카운트만 줄어드는 경우는 정정이 잦아 기준을 2회로 따로 뒀다.

### 노트북이 자면 없던 타석이 생긴다

절전에서 깨어나면 폴러가 **몇 시간 전 스냅샷과 지금 스냅샷을 이어 붙여** 비교한다.
"나성범 → 아웃, +10점" 같은 타석이 만들어졌다.

폴링 간격이 90초를 넘으면 기준점을 통째로 버린다. 다음 스냅샷부터 새로 시작한다.

### 타석 시작 시점을 기준으로 잡아야 한다

타석 결과는 "직전 스냅샷 대비 변화"로 보면 틀린다. 한 타석 안에서도 스냅샷은 여러 번
바뀌기 때문이다. **타석이 시작된 순간**을 따로 기억해 두고 그것과 비교한다.

경기 마지막 타석은 `IN_PROGRESS → FINISHED` 전환에서 따로 감지한다 — 그러지 않으면
끝내기 타석이 영영 정산되지 않는다.

### 23:55 크론은 노트북이 자면 그냥 넘어간다

일간 요약이 10/3~10/6 나흘치 통째로 비었다. 크론을 믿는 대신, **날짜가 바뀐 걸 처음
알아챈 순간** 전날 요약을 뱉도록 바꿨다.

### 터널이 살아 있는 채로 죽는다

AWS 없이 월 0원으로 돌리려고 Cloudflare Quick Tunnel을 쓴다. 그런데 `cloudflared`는
**프로세스가 멀쩡한 채로 연결만 잃고** 재시도를 무한 반복한다. `ps`로도, 포트로도,
로그로도 정상으로 보이는데 외부에서는 아무도 접속할 수 없다. 이걸로 하루, 그리고 13일을
날렸다.

그래서 감시는 **공개 주소로 실제 요청을 보낸다.** Cloudflare 엣지를 한 바퀴 돌아오는지가
유일하게 믿을 수 있는 신호다. 죽었으면 끊고 다시 연결한 뒤, **새 주소가 실제로 열리는 걸
확인하고** 앱 설정에 기록한다.

> 21일 연속 무인 운영에서 13번 끊겼고, 13번 모두 스스로 복구했다.

자세한 내용은 [TUNNEL.md](TUNNEL.md).

## 구조

```
game/live/          실시간 감지 — 폴러, 타석 판정기, 스냅샷 검증, 중계
game/               경기 일정·결과 크롤링
bet/                내기 제안·수락·자동 정산
room/               초대코드 방
user/               가입·탈퇴·응원 구단
safety/             신고·차단 (앱스토어 심사 요건)
security/           Firebase 토큰 인증
```

핵심인 `AtBatDetector`는 **상태 없는 순수 함수**다. 스냅샷 두 개와 타석 시작 시점을 받아
판정만 내린다. 그래서 테스트에 실제 경기 상황을 그대로 넣어볼 수 있다.

테스트 27개 파일. 고친 버그마다 **고친 코드를 되돌려 테스트가 실패하는지 확인**하고 넣었다.

| 프로파일 | 용도 |
|---|---|
| `local` | H2 인메모리, Swagger·H2 콘솔 켜짐 |
| `local-tunnel` | H2 파일, 콘솔 꺼짐, **Firebase 인증 필수** |
| `prod` | MySQL, `ddl-auto: validate` |

`local-tunnel`에서 Firebase를 필수로 둔 이유: 인증 필터는 Firebase가 없으면 로컬 개발
모드로 떨어져 **Authorization 헤더 문자열을 그대로 uid로 신뢰한다.** 공개된 주소에서는
그게 곧 계정 사칭이다. 그래서 초기화에 실패하면 조용히 뜨는 대신 기동을 중단한다.
